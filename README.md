# SynthSenses

[![Ask DeepWiki](https://deepwiki.com/badge.svg)](https://deepwiki.com/parina004/socialmedia-content-analysis)

An adaptive AI framework that concurrently detects synthetic media and predicts social media virality, with LLM-based explainability.

AI-generated content is everywhere, and the gap between real and synthetic footage is closing fast. At the same time, platforms are flooded with content competing for attention, and most creators are guessing at what actually works. SynthSenses addresses both problems in a single system: it analyses a video and tells you whether it is real, AI-generated, or a deepfake, and whether it has what it takes to go viral, with a written explanation grounded in research rather than a bare label.

**Live:** https://synthsenses.netlify.app. Actively in development; the full inference pipeline runs locally due to model memory requirements on free hosting.

## What It Does

Upload a video and the system runs two independent analyses:

- **Synthetic media detection**: classifies the video as Real, Deepfake, or AI-Generated, each with its own forensic signature, rather than collapsing them into a single "fake or not" binary.
- **Virality prediction**: analyses visual quality, motion, audio characteristics, facial presence, and upload metadata to predict whether the video is likely to go viral, and surfaces which factors are driving the prediction.

Both results come back with a confidence score and a plain-language explanation generated by an LLM grounded in a research knowledge base via retrieval-augmented generation (RAG).

## Under the Hood

### Model A: three-stream cascade detection

The input video is sampled at one frame per second (up to 30 frames) and passed through three parallel feature streams:

1. **EfficientNet-B4** (ImageNet-pretrained, frozen), a 1,792-dimensional visual feature vector capturing texture, colour distribution, and perceptual quality.
2. **ForensicCNN**, a custom CNN trained from scratch on 6-channel DCT and SRM frequency representations of each frame, producing a 256-dimensional embedding that exposes generative-model noise signatures invisible in the pixel domain.
3. **MediaPipe FaceMesh**, 468 facial landmarks reduced to 16 geometric ratios (eye, nose, mouth, symmetry) that catch the facial proportion distortions left behind by face-swap deepfakes.

The three streams are fused into a 2,064-dimensional vector and classified by a two-stage XGBoost cascade:

```
if P(AI-Generated) >= 0.65:   label = AI-Generated
elif P(Deepfake)    >= 0.40:   label = Deepfake
else:                          label = Real
```

The cascade was trained on FaceForensics++, DFDC, Celeb-DF v2, WildDeepfake, and AI-generated clips collected from AnimateDiff, CogVideoX, RunwayML, Stable Diffusion, VideoCraft, VideoPoet, and other sources. It achieves **90.83% accuracy and a macro F1 of 0.908** across all three classes on the held-out test set, with only one sample confused between the Deepfake and AI-Generated classes.

### Model B: 22-feature virality prediction

Twenty-two content-based features are extracted from the video and its metadata, split across three groups: 7 visual (BRISQUE quality, colour vibrancy, motion intensity, face presence, facial emotion, thumbnail brightness), 5 audio (tempo, RMS energy, speech ratio, zero-crossing rate, beat strength), and 10 metadata (title sentiment, title length, upload hour/day, tag count, and more). None of the features depend on the creator's subscriber count or posting history, so the model works for any channel, including new or small creators.

Videos are labelled Viral (top 20% by engagement percentile) or Not Viral (bottom 40%), with the middle 40% excluded to reduce label noise. A LightGBM classifier, tuned with Optuna over 50 trials of 5-fold cross-validation, achieves a **ROC-AUC of 0.854** and 80% accuracy on the held-out test set.

### LLM explainability layer

Once both models return a result, the raw output is turned into a written explanation:

1. A RAG query built from the detection result retrieves relevant chunks from a ChromaDB knowledge base (11 peer-reviewed papers plus system documentation, embedded with `all-MiniLM-L6-v2`).
2. The retrieved chunks, model outputs, and feature values are inserted into a domain-specific prompt.
3. The Groq API (`llama-3.1-8b-instant`) generates a forensic verdict and a virality analysis with practical posting tips, grounded in the retrieved research rather than the model's own assumptions.

### Agentic orchestration variant

An alternative agentic pipeline (`agent/`) replaces the fixed API handlers with a LangChain ReAct agent running `llama-3.3-70b` on Groq. The agent has six tools available: `run_synthetic_detection`, `run_virality_prediction`, `search_knowledge_base`, `fetch_trending_hashtags`, `generate_forensic_report`, and `generate_virality_report`. It decides which to call and in what order based on intermediate results, rather than following a fixed sequence. For example, a borderline detection confidence can trigger an extra knowledge base search before the report is written.

## Architecture

```
frontend/          Lightweight HTML/CSS/JS frontend, deployed to Netlify
api/main.py         FastAPI backend exposing the analysis endpoints
model_a/             Synthetic media detection: feature extraction, cascade inference, training
model_b/             Virality prediction: feature extraction, inference, training
llm/                 Prompt templates and report generation via the Groq API
rag/                 ChromaDB vector store, retriever, and source documents
agent/               LangChain ReAct agentic orchestration variant
docs/                Project documentation and reports
```

## API

The backend exposes a REST API:

| Endpoint | Method | Description |
|---|---|---|
| `/health` | GET | Liveness check |
| `/analyze/synthetic` | POST | Upload a video, get back Real / Deepfake / AI-Generated with confidence and explanation |
| `/analyze/virality` | POST | Upload a video (plus optional title, upload hour/day, tags), get back a virality score, label, top features, and explanation |

Uploaded files are limited to 100 MB, restricted to `video/mp4`, `video/quicktime`, `video/x-msvideo`, and `video/webm`, rate-limited to 10 requests per IP per minute, and automatically deleted 5 minutes after processing.

## Running Locally

### Backend

```bash
pip install -r requirements.txt
uvicorn api.main:app --reload
```

The backend needs a `.env` file with, at minimum, `GROQ_API_KEY` set. Model weights (`model_a/forensic_cnn.pth` and `model_b/model.pkl`) are downloaded automatically from the Hugging Face model repository at Docker build time; when running outside Docker, make sure these files are present locally before starting the server.

### Frontend

`frontend/` is a static site. Serve it with any static file server, or open `frontend/index.html` directly and point `frontend/js/api.js` at your local backend URL.

### Docker

```bash
docker build -t synthsenses .
docker run -p 7860:7860 --env-file .env synthsenses
```

## Deployment

The backend runs as a Docker container on Hugging Face Spaces (free CPU tier, 16 GB RAM), with model weights pulled from a separate Hugging Face model repository at build time. The frontend is hosted on Netlify and talks to the backend over HTTPS. `render.yaml` is also provided for deploying the backend to Render as an alternative.

## Limitations and Future Work

The Real class has the weakest F1 (0.85), meaning some legitimate videos with unusual compression or texture are still flagged as synthetic. The virality model's recall on the viral class (65%) reflects the ceiling on what can be predicted from content alone, since network effects and platform algorithmic boosts are outside its view. The RAG knowledge base is static and will need periodic updates as new research is published. Planned future work includes audio-visual synchrony analysis for Model A, optional social signals for Model B, an automated RAG update pipeline pulling from arXiv, and evaluating the agentic variant on live moderation tasks.
